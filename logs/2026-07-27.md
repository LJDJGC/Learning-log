### 💡 学びのポイント
**新規習得：**
- **`e.preventDefault()` の意味**:
  フォーム送信時のデフォルト動作（ページリロード）を止める
  止めないと `setSessions` で更新した状態がリロードで消える
- **`crypto.randomUUID()`**:
  ブラウザ標準の UUID 生成機能。ライブラリ不要で一意のIDが作れる
- **`sessions.filter(s => s.id !== id)`**:
  削除したいID以外だけ残す＝削除処理

**理解深化：**
- **fire-and-forget パターン（今回の実装の意図）**:
  - `await setDoc(...)` をやめて `setDoc(...).catch(...)` にした
  - localStorage を先に書き、Firestore は待たない
  - 広告ブロッカーで Firestore がブロックされても画面は止まらない
- **三項演算子での条件分岐表示**:
  `{user ? <SignOut /> : <SignIn />}`
  ログイン状態によって表示を切り替える典型的なパターン

- **`e.preventDefault()` purpose**:
  Prevents the default form submission behavior (page reload)
  Without it, `setSessions` state would be lost on reload
- **`crypto.randomUUID()`**:
  Browser-native UUID generation, no library needed
- **`sessions.filter(s => s.id !== id)`**:
  Keep everything except the ID to delete = delete operation

**Deeper Understanding:**
- **Fire-and-forget pattern**:
  - Changed from `await setDoc(...)` to `setDoc(...).catch(...)`
  - localStorage writes first, Firestore is not awaited
  - UI never freezes even if ad blocker blocks Firestore
- **Ternary for conditional rendering**:
  `{user ? <SignOut /> : <SignIn />}`
  Classic pattern for switching UI based on login state
