### 💡 学びのポイント

**新規習得：**
- **GitHub貢献グラフの条件**:
  コミットが草になるのは「デフォルトブランチ（main）に存在するコミット」のみ。
  フィーチャーブランチにpushしても、mainにマージされなければ草にならない。
  → これが「草が濃くならない」原因だった。

- **CIの重要性**:
  feat/handson-firebase にはCIワークフロー（lint/tsc/test）がある。
  mainにはまだCIがないため、pushしてもテストが走らない状態は危険。
  CIをmainにマージすることで、品質保証が自動化される。

**理解深化：**
- **ブランチ戦略の実践**:
  feat/handson-* で作業 → 動作確認 → mainにマージ という流れを体験。
  面接で「Gitのブランチ運用どうしてる？」と聞かれたときに話せる内容になった。

- **recallブランチの位置づけ**:

```tsx
const getLevel = (minutes: number, maxMinutes: number): number => {
    if (minutes === 0) return 0;
    if (maxMinutes === 0) return 1;
    const ratio = minutes / maxMinutes;
    if (ratio < 0.1) return 0;
    if (ratio <= 0.25) return 1;
    if (ratio <= 0.5) return 2;
    if (ratio <= 0.75) return 3;
    return 4;
}
```
