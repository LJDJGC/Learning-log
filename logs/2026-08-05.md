### 💡 学びのポイント

**新規習得：**
- **GitHub機能ブランチマージの実践手順**:
  ① ブランチで開発 → ② ローカルでlint/型チェック/テスト確認 →
  ③ GitHub WebでPR作成 → ④ CIが通るのを確認 → ⑤ Mergeでmainに統合。
  マージ後は `git checkout main && git pull` でローカルを同期する。

- **マージコミットの意味**:
  フィーチャーブランチをマージすると、その時点で作られた目印のコミットになる。
  このコミットが「作業ブランチの成果物をmainに受け渡した記録」だと理解できた。

**理解深化：**
- **`.env.*` のgit管理について**:
  `.gitignore` の `.env*` は原則すべての.env系ファイルを除外する。
  しかし `.env.example`（見本）は例外的に git管理して配布するのが正しい運用。
  現在は見本も除外され、しかも内容が古い（Clerk/Supabase時代のまま）という
