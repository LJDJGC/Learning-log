### 💡 Key Learnings
**Newly Acquired:**
- Hydration Mismatch: occurs when the HTML rendered by SSR doesn't match the client's first render. The error here was an initial-render divergence: the server rendered the list while the client rendered the spinner
- `NEXT_PUBLIC_` environment variables are **inlined into both the server and client bundles at build time**, so both sides can reference identical values
- `react-hooks/set-state-in-effect` rule: synchronous setState inside useEffect is banned by ESLint because it causes cascading re-renders

**Deeper Understanding:**
- `auth` depends on `typeof window !== "undefined"`, so it is **always null during SSR (on the server)**. Therefore `auth` must never be used as a state initial value
- The essence of avoiding hydration mismatches is "render the same initial value on both server and client". I used the presence of environment variables — information identical on both sides — as the initial value
- A well-designed initial value also eliminates the need for synchronous setState, resolving the ESLint violation at the same time

**Troubleshooting:**
- Hydration error cause: `useState(() => (!auth || !db ? false : true))` evaluated to `false` (list) on the server but `true` (spinner) on the client
  → Introduced `isFirebaseConfigured` (based only on env var presence) so both sides get the same initial value
- Legend fix revert: checking the working tree diff with `git diff` revealed the legend fix (separated with `flex items-center gap-1`) had reverted to the broken form
  → Restored the correct committed state with `git checkout HEAD -- src/components/GrassCalendar.tsx`
